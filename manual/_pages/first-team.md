このページでは YAML を白紙から書かず、Web 画面の `New definition` から最小構成のチームを作ります。
参照するエージェントはあらかじめ登録されている必要があります。

## 1. New definition を開く

`http://localhost:5049/definitions/new?kind=team` を開きます。
画面上部の `New definition` から入り、種類で「チーム」を選んでも同じ画面になります。

画面には、エージェント、チーム、グラフの種類カードと、テンプレートや複製方法を選ぶ欄が表示されます。
画面全体の見方は[New definition のスクリーンショット]({{ '/assets/images/new-definition.png' | relative_url }})を参照してください。

![New definition の画面。種類、テンプレート、役割の選択欄に番号付きの注釈があります。]({{ '/assets/images/new-definition.png' | relative_url }})

1. 作成する定義の種類
2. 用途別のテンプレート
3. 役割へ割り当てるエージェント

## 2. テンプレートを選ぶ

「テンプレートから」を選び、「レビュー体制」をクリックします。
レビュー体制は、統括、実装役、検証役の3名で、作ったものを別のエージェントが確かめるテンプレートです。

期待される状態は、テンプレートカードが選択状態になり、下に役割ごとの選択欄が表示されることです。

## 3. 役割へエージェントを割り当てる

「統括」、「実装役」、「検証役」の欄で、登録済みのエージェントを1つずつ選びます。
同じエージェントを複数の役割へ割り当てないほうが、最初は会話の違いを追いやすくなります。

選択すると、画面下または右側の「このチームはこう動きます」という説明が更新されます。
統括が目標を受け、担当へ作業を渡す説明になっていることを確認してください。

## 4. 名前を付ける

`name` に、まだ使われていない名前を入力します。
フォルダー名にもなるため、英小文字、数字、ハイフン、アンダースコアだけを使います。
例として `my-first-team` のような名前にします。

期待される状態は、名前のエラーが消え、「作成」ボタンが有効になることです。
既存の名前や大文字、空白を含む名前では作成ボタンが無効になります。

## 5. 作成して内容を確認する

「作成」を押します。
保存後はチーム編集画面へ移動し、統括、メンバー、会話の許可関係を確認できます。
画面には書き出される YAML も表示されます。

保存直後に一覧へ表示されても、実行プロセスが起動時に定義を読み込むため、実行へ反映するには Host と Web の再起動が必要です。
配布版ではトレイメニューの「更新」を使います。

## 6. チームを実行する

`http://localhost:5049/missions/new` を開き、次のように指定します。

- 対象種別：`Team`
- 対象：作成したチーム
- 目標：担当へ渡したい短い作業

「ミッションを開始」を押すと、作成したチームの Team Room が開きます。
統括から担当への委譲が表示され、右側の Mission 欄で対象チーム名を確認できます。

## 7. YAML で細かく調整する

画面で作った定義も、実体は `src/WorkAgents.Agents/teams/<name>/team.yaml` です。
直接編集する場合は、メンバー間の直接会話、委譲の深さ、並列数、進捗のない往復の上限を設定できます。
各キーの意味は[チームを作る]({{ '/pages/teams/' | relative_url }})、画面の検証と保存の注意は[画面から定義を作る]({{ '/pages/definition-editor/' | relative_url }})を参照してください。

自分で YAML を書く代わりに、同梱の Agent Skill を使って Claude Code のようなコーディングエージェントに作らせることもできます。手順は[画面から定義を作る]({{ '/pages/definition-editor/' | relative_url }})の「コーディングエージェントに作らせる」を参照してください。
